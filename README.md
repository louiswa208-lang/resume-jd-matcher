# 逐条核对 · 简历与岗位要求匹配

把岗位描述拆成一条条要求,逐条对照简历给出判断:哪些满足、哪些有差距、哪些只是简历里没写。
每条判断都附上简历原文作为证据,分数由固定规则算出。

设计文档(含每个决策的理由和被否决的方案):[`docs/design.md`](docs/design.md)

## 这个项目在解决什么

飞书、腾讯会议这类工具的 AI 功能能生成摘要,但回答不了「这件事跟我有什么关系」。
求职场景里的同类问题是:市面上的简历匹配工具给一个百分比,但说不清这个数字怎么来的,
也分不清「你不满足」和「你没写」。

这个项目的三个核心主张:

1. **分数由规则算,不由模型给。** 模型只判断每条要求满足与否,总分是代码里的加权公式算出来的。
   同一份简历刷新两次分数不会变,而且能回答「为什么是 66 分」。
2. **判断必须有出处。** 每条判断都要附上简历原文片段。找不到证据时,系统明说「证据不足」,
   而不是硬编一个体面的分数。
3. **「没写」不等于「没有」。** 证据不足单独成一类,用靛蓝色而不是警告色标注,
   并引导用户补充后重新评估。

## 技术结构

```
浏览器
  ├─ pdf.js 解析简历 PDF → 纯文本(文件不离开浏览器)
  └─ POST /api/analyze
        ├─ IP 限流
        ├─ 第一步:从 JD 抽取要求清单(结构化,非流式)
        └─ 第二步:逐条比对简历(流式,一条一条返回)
              └─ 前端边收边渲染 → 规则算分
```

两步拆分不是为了好看:第一步跑完,前端才**真的知道**要核查哪几条,
所以界面上的逐条进度是真实的,不是写死的动画。

| 文件 | 作用 |
|---|---|
| `src/lib/scoring.ts` | 算分规则(纯函数,不含模型调用) |
| `src/lib/pipeline.ts` | 两步 pipeline 与 prompt |
| `src/lib/pdf.ts` | 浏览器端 PDF 解析 |
| `src/lib/example.ts` | 预置示例数据 |
| `src/app/api/analyze/route.ts` | 流式接口 |

## 已知局限

- **限流是软门槛。** 进程内内存计数,serverless 多实例下会各算各的。
  足够拦住顺手多点几次,拦不住刻意刷。换成 Redis / Vercel KV 只需改
  `src/lib/rate-limit.ts` 里的两个函数。
- **扫描件 PDF 提取不出文字。** 已做诚实降级:检测到提取为空时提示用户粘贴文本,
  而不是假装解析成功。
- **不存任何数据。** 因此拿不到线上的真实判断数据,评估要靠自建评估集
  (手工标注 15~20 组简历 × JD,统计准确率和误判类型)。

## 部署

Vercel 一键部署,记得在项目设置里配置 `DEEPSEEK_API_KEY` 环境变量。

DeepSeek 的 API 从海外和国内服务器都能调通,所以如果后续要迁到国内云,
**AI 相关代码完全不用动**,只需搬前端和后端。
